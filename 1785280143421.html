Open questions / assumptions for the build team

  1. Trucking Ticket & Service Ticket — not yet outlined; this prototype only builds out Field Ticket.
  2. Mud Transfer — shown as a disabled placeholder under Work Type; fields to be defined later.
  3. All type-to-filter fields (Job Number, Employee, 3rd Party Company, Equipment Type, Owned Serial, Containment Type, Vehicle Number, Approving Manager) use a native combobox pattern: the list filters as you type, but any value typed that isn't on the list is still accepted as free-form entry. Built with HTML's input+datalist here for speed — production version should use a proper searchable-combobox component with the same filter+free-entry behavior.
  4. Job Number lookup — sample list of 4 jobs with hardcoded Customer/Lease/Rig; production needs a live Job master lookup.
  5. Employee & 3rd-party vendor lists — sample data; production needs a live roster / approved-vendor source.
  6. Equipment serial lists (Aly-owned DMP/RBFOW/FB/EMMP) — small sample set; production needs the live Equipment Inventory master (849 assets), and Sub-Rented entries need to write new vendor/serial combos back into that inventory rather than just being a free lookup.
  7. Equipment Type free-form entry — if a typed value doesn't match one of the 6 known types (DMP/RBFOW/FB/EMMP/Containment/Other), the form falls back to the "Other" field set (ownership + description) so nothing is lost. Worth confirming this is the right fallback.
  8. Visit-level fields (description, 4 times, standby, vehicle, mileage) — confirmed as ONE set per ticket covering the whole visit, not repeated per equipment piece.
  9. Standby windows — now an uncapped repeater (add as many as needed), matching the Equipment pattern.
  10. Equipment — uncapped repeater; add as many pieces as the visit needs.
